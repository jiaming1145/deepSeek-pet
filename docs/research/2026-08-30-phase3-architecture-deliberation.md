## Claude's opening position (round 1)

1. Simulation (mood/energy/affection, rhythms, absence, proactive scheduler) in MAIN as a pure deterministic `packages/sim` state machine at 2 Hz, persisted to kv every minute and on quit, emitting coarse `sim:state` snapshots.
2. Behaviour selection + all frame-rate work (idle pool, saccades, breath/blink/physics, touch reactions, drag physics, expression decay) in the RENDERER stage controller, fed by the snapshot + `behaviors.json` (weights + conditions); utility-style weighted random with last-N exclusion, seeded rng; no behaviour tree.
3. Arbitration: fixed priority stack touch > LLM ACT > proactive/idle; LLM expressions persist 90 s then decay.
4. Proactive speech: scheduler in main (owns clocks, DND/fullscreen/lock via VisibilityState, DeepSeek client); templates in the character bundle with a 30-day `said` ledger in kv.
5. Memory: node:sqlite; facts extracted by a bounded `deepseek-v4-flash` call every N turns (JSON schema, dedup by normalised key); retrieval via FTS5 if available else CJK bigram index; ≤ 5 facts + summary in the latest user message so the static prefix stays byte-stable.
6. Opaque-pixel hit-testing via a ¼-res alpha readback per frame while the cursor is over the window.
7. Memory footprint: lazy key/chat windows, keep the bubble window; expect ~450 MB; propose amending the 250 MB bar.

## GPT round 1 (verbatim substance)

**Agrees with:** main/renderer split, utility-weighted idle selection, main-owned proactive scheduler, SQLite memory. **Rejects:** single arbitration stack, framebuffer readback, renderer-owned native window physics, relaxing the memory bar without evidence.

1. **Sim in main with two clock domains.** `packages/sim` = Electron-free reducer. Monotonic time for absence, cooldowns, expression leases, backoff, deadlines; wall-clock only for morning/night/meal phases. Events `USER_ACTIVITY`, `LOCKED/UNLOCKED`, `SUSPEND/RESUME`, `CLOCK_PHASE_CHANGED`; never assume every 500 ms tick happened. "Notice return within 1 s" needs the presence source sampled every tick + immediate reconciliation on unlock/resume/input. Invariant: after 5 min absent `presentationMode = nap` may change; relationship/mood/energy/affection never decay or accrue while absent; on return emit a wake reaction, no catch-up. Versioned snapshot every minute + on clean shutdown; quit awaits the final write before SQLite close; no SQLite work inside the 2 Hz reducer.
2. **Utility selector, no behaviour tree.** Pure seeded selector + a small state machine inside each multi-step behaviour (walk, nap, stretch, fling, landing); frame-rate application in the renderer. `behaviors.json` needs a schema: stable id, weight + liveliness scaling, declarative conditions (no eval), cooldown, min/max duration, required motion/expression resources, interruptibility, optional locomotion request, tags (morning, meal, tired, cursor-near). Validate on load. "No repeats" needs a fallback: keep several neutral behaviours always eligible; when last-N exclusion empties the set pick least-recently-used; immediate repetition impossible. Select at behaviour completion or a deadline, not per frame.
3. **Per-lane arbitration leases instead of one stack.** Failure of one stack: a 90-s LLM expression blocks unrelated idle motion/gaze. Lanes: body motion (touch > LLM motion > idle); expression (touch overlay > LLM 90-s lease > sim/idle); gaze (touch target > LLM look lease > cursor-rest > idle saccade); locomotion/window (active drag > LLM walkTo > idle walk); speech (active user response > approved proactive); additive layers (breath/blink/physics) outside arbitration. The 90-s rule applies to the expression, not the whole ACT; touch overlays then restores the remaining lease. Every command carries source, generation, issue time, expiry, validated lane payload; completion callbacks compare generation (same concern as the Cubism motion-finish tracker). LLM boundary validates a bounded protocol before IPC: `emotion`/`motion` character enums, `look` symbolic or bounded normalised coords, `walkTo` symbolic anchors or main-clamped coordinate, `say` bounded + stripped of control tags/invalid Unicode; unknown → rejected explicitly.
4. **Renderer animates; MAIN owns native window physics.** Main owns setPosition, work-area topology, DPI coordinates, display-removed/metrics-changed, visibility lifecycle. Flow: renderer reports opaque contact + pointer-to-avatar anchor → main runs a bounded spring/damper window motor at 30–60 Hz, clamps with the grabbable region → on release derives bounded velocity from recent samples, runs fling/gravity/landing → display changes rebase the active physics → main sends velocity/landing events for tilt/squash/landing animation. Weight lag must not let the cursor leave the avatar; use captured/global cursor during drag and suspend hover click-through switching. `walkTo` goes through the same motor.
5. **No ¼-res framebuffer readback per frame.** `readPixels` forces ANGLE GPU/CPU sync; whole-buffer reads at 30 Hz are incompatible with 4 % idle CPU and still misclassify thin hair/fingers/holes. Use a picking path: compact offscreen picking target with body-part ids as colours, read ONE pixel under the cursor on forwarded cursor movement, low-rate resample while stationary only if pose can change; if 1-px sync reads still stall, double-buffer with PBOs/fences (one-frame delay). Distinguish opaque-vs-transparent AND semantic part. Cubism rectangular hit areas are not opaque-pixel testing. Combine with DOM hit regions for click-through.
6. **Proactive: atomic gate, checked twice** (before generation and immediately before display — typing/fullscreen/lock/DND can start during generation). One in-flight attempt; ledger transacted atomically: ≤ 1 displayed per rolling 20 min; ≤ 3 unanswered/day with backoff; persona cap 2/day; no active user response; not typing/fullscreen/locked/suspended/DND/user-hidden; ≥ 60 s since input; no template id repeat within 30 days. Define charging (reservation vs display) — charge on display but reserve in flight; persist reservation + outcome so restart cannot double-fire. 30-day rule enforceable on template ids, not semantic equivalence of LLM output. Never show bubble/chat while the verdict is hidden; replay `bubbleWanted` only through that gate.
7. **Memory.** CJK retrieval: default FTS5 tokenisation is weak for unsegmented Chinese — build an explicit CJK bigram index (+ Latin normalisation) or verify the bundled tokenizer first. Keep fact provenance, confidence, updated-at, tombstone/correction; key-only dedup merges distinct facts. Caching: putting summary/facts in the latest user message is compatible only if earlier wire messages stay byte-identical — persist the per-turn envelope, never rewrite earlier envelopes, append the memory block only to the new turn; summary compaction is an intentional cache reset; measure real cached-token counters over 20 turns; enforce the 600-token summary with a tokenizer/estimator. Fact extraction + summary trimming serialised, cancellable, drained before DB close. *(Claude rebuts the append-only requirement in round 2 — the miss is bounded to one exchange.)*
8. **TIMEOUT_SIGNAL as product state.** Intercept the exact normalised command in main; `TIMEOUT_SIGNAL` → plain mode, `PERSONA_LOAD` → persona; two fixed cacheable system profiles (one legitimate cache reset per switch); plain mode disables mannerisms and LLM ACT (or neutral visual state); safety/output grammar stays in both.
9. **Activity sensing: local, aggregate, opt-in, default off.** Key-down timestamps only (no values/scan codes/clipboard/targets), rolling count in memory, no raw stream persisted. Active window: executable/app-category allow-list, no titles, never sent to DeepSeek without separate consent, exclude own windows. Battery via Electron/Windows events. Renderer receives coarse derived state only.
10. **Liveliness knob: one normalised 0..1 value with one monotonic mapping** (idle interval, high-energy weight, saccade rate/amplitude, touch probability/intensity, locomotion probability, proactive eligibility probability) in one shared pure module; hard caps stay hard; never alters affection/honesty/memory/safety/absence.
11. **Do not amend 250 MB before profiling the right topology:** pet eager; bubble lazy-created and destroyed after an idle grace; chat/key lazy, ideally one reusable utility window with mutually exclusive routes; destroy aux windows on close; stop hidden render/ticker work; production build, no DevTools; aggregate main+renderer+GPU+utility with a documented Windows metric. Reconsider the merged DOM bubble empirically (whole-window `setIgnoreMouseEvents` is not a blocker — the avatar already needs dynamic hit testing; the real costs are enlarged bounds, anchoring, clamping). Negotiate the bar only with measurements.
12. **Testing/evidence:** trace sidecar (monotonic + wall time, presence/visibility verdicts, eligible/weights/selected/seed, lane/source/generation, suppression reason + ledger decision, touch part + opacity, drag velocity/work area/clamp/landing, FPS/frame time/CPU/memory; no keys, titles, user text). Boundary tests: absence at 299.9/300 s and return < 1 s; suspend/resume + lock/unlock without mood progression; clock rollback/DST/midnight caps; typing or fullscreen during proactive generation; tap pre-empting then restoring a 90-s expression; stale motion/fling completion after a newer generation; monitor unplug during drag and fling; transparent holes + adjacent part boundaries; renderer reload with replay; 20 append-only turns with real cache counters; 60-s unattended run at production settings; separate 20-s interaction recording; resource measurement WITHOUT recording overhead.

## GPT round 2 — CONVERGED (verbatim substance)

**A. Caching — append-only wire history is unnecessary.** Replacing the previous dynamic envelope with raw text is a *bounded frontier miss*: common prefix = system + history through assistant n−1; uncached = raw user n + assistant n + the current envelope n+1 (the current envelope is always new — do not omit it from the arithmetic). Measure `hit / (prompt_cache_hit_tokens + prompt_cache_miss_tokens)` per request and token-weighted over the 20 turns; the live probe is authoritative (block granularity, expiry, routing). Keep raw history. Document the intentional cache resets: trimming/summarisation removing leading messages; persona↔plain profile switch; any system-prompt/serialisation change; new conversation. No change unless the live metric < 70 %.

**B. CPU mesh + alpha picking — acceptable, not automatically exact.** Must honour: drawable visibility + dynamic opacity; model opacity; deformed vertices after update; the SAME model/MVP transform as rendering; render order (not index order); normal AND inverted clipping masks incl. mask deformation/opacity; culling/winding; UV orientation with BILINEAR sampling (nearest disagrees on thin hair/antialiased edges); multiple translucent layers compositing above threshold; additive/multiply meshes policy; a declared final-alpha threshold; explicit drawable→semantic-part metadata in the character bundle with `participatesInHitTest` (highlights, blush, shadows otherwise steal hits from `face`/`torso`). Define topmost-contributing vs anatomical part. Recompute on pointer move, on animation under a stationary pointer, and at click/tap with exact coordinates. Test oracle: render representative poses and compare the CPU predicate against framebuffer pixels (clipped/inverted-clipped meshes, holes, antialiased edges, overlapping translucent meshes, additive highlights, culling, every body part). "Microseconds" is a hypothesis until measured on Haru; add triangle bounds/spatial rejection only if needed.

**C. Main-authoritative motion with 30 Hz snapshots — acceptable** if motor rate (30–60 Hz native) and renderer presentation (RAF interpolation) are separated. Snapshot = `{generation, monotonic ts, phase, velocity, cursor/target lag vector, contact state}`; landing = generation-stamped one-shot with impact velocity/impulse (squash from impact, not from `phase=landed`; stale landing must not affect a newer drag). Renderer keeps the model-local contact anchor from picking; main keeps the native pointer offset and follows GLOBAL cursor state after the cursor leaves the window. During drag/fling: suppress hover click-through changes; rebase on display topology changes; clamp target and result in work-area DIPs; invalidate callbacks/snapshots by generation on cancel/reload/new drag.

**D. Package layout — accepted with two amendments.** (1) `packages/behaviors` platform-neutral: schema/types, declarative condition evaluator, seeded selector + LRU policy, structural validation; NO fs/Electron/WebGL/app-protocol (bundle I/O lives in an app adapter / the stage asset loader). Two-stage validation: structural at JSON load, resource validation once Cubism motions/expressions/drawable ids are known; FAIL the character validation/evidence run if < 12 usable behaviours remain after binding (silent disabling would violate D1). (2) No god-object `sim-service`: `SimService` (2 Hz reducer dispatch, clock/sensor reconciliation, snapshot persistence), `WindowMotionController` (drag/fling/walk motor + display topology), `ProactiveController` (atomic gate, generation, second suppression check, ledger), activity sensor adapter (aggregate opt-in), and the EXISTING `BrainService`/shared brain abstraction for DeepSeek — no second pipeline; proactive generation joins the same cancellation + shutdown drain. Dependency direction: `packages/sim` (pure state, clocks, policy, liveliness) · `packages/behaviors` (pure schema, conditions, selection) · `packages/memory` (facts, bigram retrieval, serialised extraction) · main adapters (Electron sensors, persistence, motor, proactive orchestration) · renderer stage (arbitration, layers, picking, drag presentation).

**Implementation gates named by GPT:** masked/composited CPU picking with the oracle test; generation-stamped motion snapshots; cross-resource behaviour validation (≥ 12 usable); live — not dry — cache measurement.
