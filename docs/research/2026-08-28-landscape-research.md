As of 2026-08-28 the DeepSeek API lineup is entirely V4: `deepseek-v4-flash` (284B MoE / 13B active, currently V4-Flash-0731), `deepseek-v4-pro` (1.6T / 49B active, V4-Pro-0813, GA since 2026-08-13) and the experimental `deepseek-v4-flash-vision-exp` (2026-08-21). The legacy aliases `deepseek-chat` and `deepseek-reasoner` (which last pointed at V3.2 then V4-Flash) were retired on 2026-07-24 15:59 UTC, so anything in your memory about V3.x/R1 model names on the API is dead. All three models expose 1M context, up to 384K output, and thinking mode is ON by default with `reasoning_effort` = `high`; for a low-latency roleplay character you must send `{"thinking":{"type":"disabled"}}` (or `reasoning.effort: "none"` on the Anthropic-format endpoint) on every request or you will pay for and wait on hidden reasoning tokens. The right model for real-time character chat is `deepseek-v4-flash` non-thinking: peak price $0.44/M cache-miss input, $0.014/M cache-hit input, $1.32/M output, and exactly half that off-peak (peak is only 01:00-04:00 and 06:00-10:00 UTC Mon-Fri, so a US-evening consumer app runs almost entirely at off-peak rates: $0.22 / $0.007 / $0.66). Base URL is `https://api.deepseek.com` (OpenAI Chat Completions + Responses API), `https://api.deepseek.com/anthropic` (Messages API), and `https://api.deepseek.com/beta` for prefix completion, FIM and strict tool schemas; the official OpenAI SDK is the intended client and there is no first-party DeepSeek client SDK (the 202k-star `@deepseek-ai/dsh` is an agent harness, not an API client). Context caching is automatic, disk-based, 64-token units, exact-prefix match only, reported via `usage.prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`, and expires after hours-to-days of disuse — so the whole game for a persistent character is an immutable system-prompt prefix plus append-only history. Tool calling and JSON mode work in both modes, but thinking mode + tools has a notorious footgun: once any assistant turn with `tool_calls` exists, `reasoning_content` must be echoed back verbatim on every later request or you get HTTP 400 "The reasoning_content in the thinking mode must be passed back to the API" (a bug that hit opencode, n8n, Warp, openclaw etc. in spring 2026); with thinking disabled the problem disappears. DeepSeek offers NO speech, transcription, TTS, or embeddings endpoints (verified against the API reference and docs sidebar) — vision now exists via the Flash-Vision-Exp model — so STT/TTS/embeddings still need separate providers. Data is processed and stored in the PRC under PRC law (Open Platform ToS effective 2026-04-29, Hangzhou jurisdiction; privacy policy updated 2026-02-10 with a training opt-out by request), which for a consumer app means either explicit disclosure plus PII scrubbing, or routing V4-Flash open weights through a ZDR provider on OpenRouter/Vercel AI Gateway. Offline mode via Ollama is weaker than hoped: Ollama's `deepseek-v4-flash` is a cloud-only tag, real local V4-Flash needs 92-162 GB of RAM via llama.cpp GGUFs, and the only small local DeepSeek models are the year-old `deepseek-r1` distills (1.5b-70b), which are reasoning models poorly suited to snappy roleplay.

Live2D's web runtime in 2026 is Cubism 5 SDK for Web R5 (tag 5-r.5, released 2026-04-02): the TypeScript Framework and Samples are on GitHub under Live2D's custom "Open Software License", while Cubism Core (live2dcubismcore.min.js) is proprietary, ships only in the zip from live2d.com, and may be embedded in your app under the Proprietary Software License's redistributable-files clause. Licensing hinges on "Latest Sales": individuals/small businesses under 10 million JPY/yr are exempt from the Publication License Agreement and pay nothing, middle-scale (<100M JPY) and large (>=100M JPY) must sign and pay (e.g. Running Royalty app plan: 50,000 JPY initial + 20,000 JPY/month/platform for middle-scale) — BUT any "Expandable Application" (avatar systems, apps that let users load arbitrary models, portals) must be reviewed and contracted by everyone including individuals, with a 300 JPY/sale-or-20%-of-sales revenue share for the small tier, so an AI-avatar app that accepts user-uploaded models is not automatically free. Model files are open-spec JSON around a binary .moc3 (moc3 v4 = Cubism 4.2, v5 = Cubism 5.0-5.2, v6 = Cubism 5.3; older Cores refuse newer moc3 with "csmReviveMocInPlace is failed"), with standard IDs like ParamAngleX/Y/Z (-30..30), ParamEyeLOpen/ParamMouthOpenY (0..1), ParamMouthForm (-1..1), ParamBodyAngleX (-10..10), ParamBreath (0..1); per-frame control follows loadParameters -> updateMotion -> saveParameters -> (blink, expression, look/drag, breath, physics, lipsync, pose) -> model.update(), and in R5 that middle block is orchestrated by a new CubismUpdateScheduler. The popular community wrapper pixi-live2d-display (1.5k stars, MIT) is effectively frozen (last push 2024-08-20, PixiJS 6/7, Cubism 2.1/3/4 only, Cubism 5 issue open since 2023); the lipsync fork pixi-live2d-display-lipsyncpatch (0.5.0-ls-8, Jun 2025, PixiJS 7) adds model.speak(url) but is also Cubism-4 era; the only active PixiJS 8 + Cubism 5 options are untitled-pixi-live2d-engine (v1.3.5, Jul 2026, 71 stars) and omniwaifu/pixi-live2d5 (Framework 5-r.5, git-only install), while the largest AI-VTuber project (Open-LLM-VTuber, 13.5k stars) abandoned the pixi wrapper for the official Web SDK to get Cubism 5. Lip sync is trivially RMS-of-audio -> addParameterValueById on the model's "LipSync" group (usually ParamMouthOpenY, but e.g. Mao uses ParamA), whereas Live2D's viseme-based Motion Sync (CRI LipSync, royalty-free, 16-bit 44.1 kHz audio, A/I/U/E/O/silence) exists for Web as a separate plugin that lags the SDK (Web plugin R2 from Mar 2025 targets SDK R3; Unity/Native got R2_1 on 2026-08-25) and needs a proprietary MotionSync Core plus a .motionsync3.json authored in the Editor. Free official models (Haru, Hiyori, Mao, Natori, Mark, Rice, Wanko, Ren, Kei, etc.) may be used, altered and shipped commercially by users under 10M JPY with the mandated credit line; collaboration/externally licensed characters (e.g. Hatsune Miku) are not commercial-safe. Commissioned models run roughly $300-1,000 half-body and $600-2,500 full-body with 1.5-3x commercial surcharges; ready-made nizima models cluster around $300/$600. VTube Studio (free, plugin API free for commercial plugins) and nizima LIVE both expose local WebSocket APIs (ws://localhost:8001 and :22022) for injecting parameters, triggering expressions/hotkeys, so a desktop-hosted avatar is a viable alternative to rendering Live2D yourself.

For a ~1 s perceived-latency companion the architecture that every working system (Open-LLM-VTuber, Project AIRI, LiveKit/Pipecat agents) converges on is: browser/Electron VAD (Silero v5/v6 via ONNX in an AudioWorklet, or TEN VAD for faster speech-end detection) → streaming or fast batch STT → LLM token stream cut into sentence-sized chunks at hard punctuation (. 。 ! ！ ? ？) with a "first chunk splits on comma" shortcut → TTS requests fired in parallel with monotonic sequence numbers → an ordered playback queue that only releases chunk N when N-1 has been sent → lip sync driven from the actually-playing audio buffer, not from the text. Latency is then max(VAD-tail, STT, LLM TTFT, TTS TTFA) rather than the sum; a realistic budget is ~200 ms VAD/endpointing + 250–400 ms LLM TTFT + 100–300 ms TTS first audio + network, so you must keep TTS first-audio under ~300 ms and the LLM first sentence short. For zh/en/ja anime-style voices in 2026 the strongest choices are: cloud — Volcengine Doubao Seed-TTS 2.0 bidirectional WebSocket (<300 ms first packet, best Chinese, cheap), MiniMax Speech 2.8 Turbo (<250 ms, 40+ langs, $60/M chars, $1.50 clone), ElevenLabs Flash v2.5 (~75 ms model latency, 32 langs incl. ja/zh, ~$0.05/1k chars), Azure Neural (needed only if you want viseme events; ja-JP has viseme IDs but no blend shapes); local on a consumer Windows GPU — Qwen3-TTS 0.6B/1.7B (Apache-2.0, 10 langs incl. ja/zh, 3-s cloning, ~2–8 GB VRAM, measured TTFA 462 ms stock → 152 ms with CUDA-graph fork on a 4090), CosyVoice 3 0.5B (Apache-2.0, bi-streaming, ~150 ms claimed), GPT-SoVITS v4/v2ProPlus (MIT, Windows one-click package, few-shot from 1 min, RTF 0.028 on a 4060Ti, api_v2 streaming_mode) which remains the de-facto anime-voice cloner, and Style-Bert-VITS2 for Japanese-only characters (MOS parity with ground truth). The 2026 "character brain" for an LLM companion/virtual pet is a deterministic simulation wrapped around a streaming LLM, not an LLM that owns the state. Persona is best expressed as a Character Card V2/V3 JSON (name/description/personality/scenario/first_mes/mes_example/system_prompt/post_history_instructions/character_book/extensions) rendered into a fixed prompt order, with the volatile stuff (mood, stats, time, retrieved memories) injected near the end of context. For emotion→expression, the two reference projects use in-band control tokens that a parser strips before TTS: Open-LLM-VTuber uses bracket keywords like `[joy]` drawn from a per-model `emotionMap` in model_dict.json, while Project AIRI uses `<|ACT {"emotion":{"name":"surprised","intensity":1},"motion":"shrug"}|>` plus `<|DELAY 1|>` and `<|CALL [...]|>`, with a 9-emotion enum (happy, sad, angry, think, surprised, awkward, question, curious, neutral). Memory should be three-tiered: rolling window + running summary (langmem-style), small LLM-editable core blocks (MemGPT/Letta pattern), and an episodic store in SQLite + sqlite-vec scored the Generative Agents way (recency decay 0.995/h, LLM importance 1–10, cosine relevance, reflection when importance sum > 150); hosted memory layers (mem0, Graphiti/Zep) are heavier than needed, and Letta's V1 server has been retired. DeepSeek has no embeddings endpoint, so pair it with OpenAI text-embedding-3-small ($0.02/M), Gemini embedding-001 (free tier), or local bge-m3 / EmbeddingGemma; DeepSeek does now offer vision (`deepseek-v4-flash-vision-exp`, ≤384 tokens/image) which makes on-trigger screenshot understanding nearly free. Proactive behavior is a solved pattern: idle timers (Open-LLM-VTuber `idleSecondsToSpeak` → `ai-speak-signal`), periodic heartbeats with a NO_REPLY convention and active-hours windows (OpenClaw), uptime/time prompts (AIRI), and idle-time precomputation (Letta sleep-time compute, ProAct). Virtual-pet loops (iPET at ACL 2025, AI-tamago, Gotchi, Tamagotchi mechanics) all keep stats/decay in a scheduler outside the LLM and feed them in as text. Safety is now statutory: California SB 243 (effective 2026-01-01) defines "companion chatbot" broadly, requires AI disclosure, a published suicide/self-harm protocol with crisis referrals, 3-hour break reminders and no sexual content for minors, annual reports from July 2027, and gives a $1,000/violation private right of action; New York, Maine and Utah have parallel laws and the FTC opened a 6(b) inquiry in Sept 2025. Runtime architecture converges on an explicit idle→listening→thinking→speaking(→interrupted) state machine (LiveKit's AgentState is the cleanest published enum), a sentence splitter between LLM stream and TTS (stream2sentence, Pipecat SentenceAggregator, Open-LLM-VTuber's comma-split "faster_first_response"), an event bus with typed messages (AIRI `input:text` / `output:gen-ai:chat:message`; Open-LLM-VTuber `MessageType`), and a "Thinking..." signal sent to the avatar the instant the request goes out so a think motion plays while tokens are in flight.

For a Live2D AI pet on Windows 11 in 2026 the field has effectively converged on Electron: the three biggest Live2D/AI companion projects (AIRI 48.5k stars, Open-LLM-VTuber 13.5k, openpets 1.1k) and most Chinese "桌宠" repos ship an Electron shell, and AIRI explicitly migrated *from* Tauri to Electron in Oct 2025 after "three months" of fighting WebView limitations (Web Audio, DevTools, compatibility). The decisive technical reason for a pet specifically is Electron's `setIgnoreMouseEvents(true, {forward: true})`, implemented on Windows with a WH_MOUSE_LL hook (PR #10183), which lets a fully click-through transparent window still receive mousemove/mouseenter so you can toggle interactivity when the cursor is over the model; Tauri has no equivalent (feature request #6164 open since Jan 2023) and pets like BongoCat (Tauri 2, 22.8k stars) work around it with global-hook crates (rdev) or a Rust cursor-polling loop, and Tauri's transparent windows on Windows still have open WebView2-upstream artifacts (ghost titlebar #14764 on Tauri 2.9.5/WebView2 144, white flash #14515). Tauri's real wins are size (tauri-live2d claims ~5 MB vs Electron installers typically 50–150 MB) and idle RAM, at the cost of WebGPU being flag-gated in WebView2 stable, WebView2 defaulting to the integrated GPU on dual-GPU laptops (#5072), and per-platform webview divergence. A plain web/PWA build cannot do transparency, click-through, always-on-top, tray, autostart or global hotkeys at all; the only floating-window primitive is Document Picture-in-Picture (Chrome/Edge 116+, Firefox 151+, no Safari), an opaque, user-gesture-gated, non-positionable window — fine as a "companion in browser" mode, not as the pet. Unity (DwmExtendFrameIntoClientArea + WS_EX_LAYERED|WS_EX_TRANSPARENT + HWND_TOPMOST, build-only, official Cubism SDK, free under $200k revenue, no splash since Unity 6, ~40 MB baseline) and Godot (Window.transparent + mouse_passthrough_polygon, gd_cubism GDExtension, 66–80 MB exe, ~200 MB idle RAM on D3D12) are viable for the character layer but make the chat/settings UI and web reuse painful; Python/PySide6 (live2d-py, DyberPet) is what the Chinese hobby scene uses but packaging/signing/hotkeys are worse and several "Python" AI pets actually pair a FastAPI backend with an Electron front end; Flutter has no Live2D package and its Windows transparency/webview plugins are 2-years-stale, and no Live2D pet uses it. On the key question: the DeepSeek API does send permissive CORS headers (verified with an OPTIONS/POST probe today: `access-control-allow-origin` echoes the Origin, `allow-credentials: true`), so a bring-your-own-key client (the AIRI / Open-LLM-VTuber model, key in local config or Electron safeStorage) is technically fine, but any key *you* pay for must sit behind a thin proxy — Cloudflare Workers/Pages Functions (free: 100k req/day, 10 ms CPU/invocation; streaming is I/O not CPU) or AI Gateway with BYOK (keys in Secrets Store, gated by `cf-aig-authorization`, DeepSeek provider supported) — with an app token plus rate limiting. Offline fallback options are Ollama (user-installed, used by Open-LLM-VTuber/git2968), node-llama-cpp inside the Electron main process (CUDA/Vulkan, must stay unpacked from asar), or WebLLM (WebGPU; works in Electron's Chromium, flag-gated in WebView2). AIRI's monorepo is pnpm workspaces + turbo with `apps/stage-web` (Vite), `apps/stage-tamagotchi` (electron-vite + electron-builder, NSIS, SignPath-signed) and `apps/stage-pocket` (Capacitor) all consuming `packages/stage-ui` (Vue 3 + UnoCSS) plus `stage-ui-live2d`/`stage-ui-three`, with platform selected via `import.meta.env.RUNTIME_ENVIRONMENT` and IPC contracts in `@moeru/eventa`; they no longer ship Tauri (only a leftover `crates/`), so "web + Electron + Tauri from one repo" is not what they do today, but the layout is exactly the shape to copy.

 - Adopt Open-LLM-VTuber's pipeline shape as the backend blueprint: per-session context object -> LLM stream -> sentence splitter (pysbd or delimiter-based) -> parallel TTS with ordered delivery -> one WS 'audio' message per sentence carrying {audio, per-frame volume/visemes, display_text, expressions/motions}. Keep the renderer dumb and the protocol explicit (Fay's Topic/Data/IsFirst/IsEnd/CONV_ID fields are a good superset).
 - Use structured emotion markers, not bare [tag]s: AIRI's <|ACT: {"emotion":{"name":..,"intensity":..},"motion":..}|> plus <|DELAY:N|> parsed by a streaming marker parser is more robust than ChatVRM-style '[happy]text', but keep a small fixed vocabulary (ChatVRM's 5-6 emotions or AIRI's ~9) and map it per model via a config file like model_dict.json emotionMap (index or expression-name) + motion groups + weighted tapMotions.
 - Pick the Live2D renderer deliberately: for a web/Electron/Tauri pet in 2026 either vendor the official Cubism SDK for Web (Cubism 5, dropped Cubism 2, proven by Open-LLM-VTuber v1.2 and awesome-digital-human) or use pixi-live2d5 (PixiJS 8 + Cubism 5, MIT, active but 11 stars). Do not start on guansss/pixi-live2d-display (last push 2024-08, PixiJS 6/7) unless you accept freezing PixiJS 7 and using the RaSan147 lipsync patch.
 - Lip-sync: ship volume/RMS -> ParamMouthOpenY first (backend-computed like Open-LLM-VTuber so the frontend stays deterministic), then upgrade to MFCC vowel estimation via wLipSync (MIT, WASM AudioWorklet, drives A/E/I/O/U) as AIRI does; avoid character-count timers (SillyTavern) and 'default mouth loop' fakes (ChatWaifu_Mobile).
 - LLM layer: everything relevant is OpenAI-compatible (base_url + api_key + model), which is exactly how DeepSeek, Ollama, LM Studio, Groq, SiliconFlow, Zhipu are wired in every surveyed repo; implement one OpenAI-compatible streaming client with tool-calling and add native adapters (Anthropic/Gemini) only if needed. AITuberKit's Vercel AI SDK factory and AIRI's xsai are the two provider-abstraction layers worth copying.
 - TTS/STT defaults that the community expects: Edge TTS (free), GPT-SoVITS and CosyVoice (Chinese voice cloning), VOICEVOX/Style-Bert-VITS2 (Japanese), ElevenLabs/OpenAI (cloud); STT via sherpa-onnx or faster-whisper with Silero VAD (@ricky0123/vad-web in-browser). Design TTS as an interface with per-engine adapters and sentence-level streaming.
 - Desktop-pet mechanics are settled: Electron transparent+alwaysOnTop+skipTaskbar window with setIgnoreMouseEvents(true,{forward:true}) for click-through (Open-LLM-VTuber, dsh-live2d-companion), or PyQt FramelessWindowHint+WindowStaysOnTopHint+WA_TranslucentBackground (Soul of Waifu, MeaPet). Add hit-area tapMotions, idle motion group, and a 'Talk' motion group during speech.
 - Licensing: prefer MIT bases (AIRI, Amica, ChatVRM, awesome-digital-human, live2d-py, pixi-live2d5, Open-LLM-VTuber backend). Be careful with Open-LLM-VTuber frontend (non-commercial 'Open-LLM-VTuber License 1.0'), AITuberKit (non-commercial custom), Fay/AI-Vtuber/Soul of Waifu (GPL-3.0), LingChat (AGPL-3.0). Cubism Core is always proprietary; never bundle Live2D sample models without checking their Free Material License.
 - If the target is a streamer/Neuro-sama clone rather than a pet, consider not rendering Live2D yourself: drive VTube Studio over pyvts (Neuro, AIRIS) and let VTS do mic-based lip-sync; keep your app as brain + audio + hotkey triggers.
 - Consider the emerging 'agent-state mirror' pattern (dsh-live2d plugins, MeaPet agent gateways, Soul Companion): map agent lifecycle events (thinking/tool-call/waiting-approval/error/done/idle) to expressions/motions in addition to chat emotions; it makes the pet useful during long agent runs.

GAPS:
 - Backend language fork never decided: repos/agent assume a Python brain (Open-LLM-VTuber blueprint, pysbd, stream2sentence, sqlite-vec, faster-whisper, GPT-SoVITS), while shell/voice assume a pure-TypeScript Electron monorepo (AIRI-style, node-llama-cpp in the main process, sherpa-onnx/VAD in worklets). An architect needs an explicit call: pure TS vs Electron + Python sidecar (packaging, IPC, PyInstaller size, AV false positives were only touched by the shell researcher).
 - Prompt-injection / untrusted-context threat model: the agent researcher recommends feeding foreground window titles, screenshots (deepseek-v4-flash-vision-exp) and tool calls (reminders, scheduler writes, macOS/Windows computer control in forks) into the LLM, but nobody covers injection via screen text/web pages, tool-permission gating, or sandboxing of LLM-initiated actions.
 - Pre-TTS text normalization and language routing: stripping markdown/emoji/kaomoji/code blocks/control tokens before TTS, per-sentence language detection for mixed zh/en/ja replies (choosing voice + TTS language per chunk), number/date/unit reading, and display-text vs spoken-text divergence. Both reference projects have this code; none of the six summaries cover it.
 - Windows desktop-lifecycle handling for an always-on pet: per-monitor DPI and multi-monitor placement of the transparent window, hiding when a fullscreen game/video is detected, powerMonitor events (sleep/resume/lock) pausing the sim and proactive speech, Electron backgroundThrottling/occlusion behaviour for a WebGL window, and battery/GPU budgets beyond the '30 FPS idle cap' one-liner.
 - Cursor-following gaze and hover in click-through mode: the live2d researcher describes the ParamAngleX/Y write slot and the shell researcher describes forward-mode mousemove, but nobody specifies where global cursor position comes from when the pointer is outside the window (screen.getCursorScreenPoint polling vs uiohook), nor blink/breath randomization tuned for a pet.
 - Audio device and echo-cancellation topology: no coverage of output device selection (AudioContext.setSinkId / Electron media device permissions), whether Chromium AEC cancels TTS played from the same renderer vs a Python sidecar or system speakers, or virtual-audio-cable setups; this directly determines barge-in false positives that the voice researcher lists as an open question.
 - DeepSeek content/moderation behaviour for companion use: DeepSeek's ToS requires developers to 'clearly disclose to your end users that the Output content is generated by AI' and forbids associating the service with 'vulgar, pornographic ... politically sensitive' content; nobody covered the model's built-in refusals on PRC-sensitive topics or romantic/adult roleplay, which a companion app will hit and needs a fallback strategy for (see lookup 2).
 - Auto-update and release pipeline: only code signing was covered. electron-updater (NSIS delta updates, GitHub Releases or Cloudflare R2 as update host), SmartScreen reputation warm-up, staged rollout, and crash reporting (Sentry/Electron crashReporter) are missing.
 - Testing/evaluation strategy: nothing on deterministic tests for the pet simulation and state machine, golden/recorded LLM-response tests, persona-consistency or emotion-tag-compliance evals for deepseek-v4-flash, or a latency regression harness (p50/p95 per stage) — the voice researcher says 'measure from day one' but no design.
 - Data lifecycle and privacy plumbing: where user data lives (%APPDATA% SQLite), encryption at rest of chat logs/screen-derived memories, export/delete (GDPR/CCPA), schema migrations, and a written privacy disclosure covering PRC processing (deepseek) plus the SB 243 disclosures (agent) — each researcher mentions a fragment, none assembles the checklist.
 - Model asset pipeline and user-supplied models: packaging format for a character bundle (model3.json + exp3/motion3 + emotionMap + voice config + character card), validation of untrusted user models (path traversal, texture size/VRAM), hot-swapping models at runtime, and how this interacts with Live2D's 'Expandable Application' licensing trap that the live2d researcher flags.
 - Turn arbitration rules: state machine exists (idle/listening/thinking/speaking/interrupted) but nobody defines what happens when a proactive heartbeat fires while the user is typing, when text and voice input arrive simultaneously, or how queued user messages during speaking are merged into one LLM turn (generation/turn IDs are mentioned only for cancellation).

CONTRADICTIONS:
 - Latency budget vs DeepSeek reality: the voice researcher budgets LLM TTFT <=400 ms to hit ~1 s perceived latency, but the deepseek researcher reports ~1 s TTFT / ~120 t/s as the first-party baseline (Artificial Analysis ~1.1 s) and only 0.32 s P50 via US-hosted V4-Flash on OpenRouter — which forfeits DeepSeek's disk-cache pricing ($0.014/M hits) that the deepseek and agent researchers build the whole prompt strategy around. The architect must pick: first-party + cache (slower) or third-party host (faster, no cache pricing, different data-residency story).
 - Live2D renderer choice: live2d recommends vendoring the official Cubism SDK for Web R5 and wrapping CubismWebFramework yourself (or evaluating untitled-pixi-live2d-engine, 71 stars, v1.3.5 Jul 2026); shell recommends starting on a PixiJS 8 + Cubism 5 fork (omniwaifu/pixi-live2d5, 11 stars, or untitled-pixi-live2d-engine); repos says either. repos never mentions untitled-pixi-live2d-engine at all, and live2d cannot confirm which Framework revision it embeds. Three researchers, three defaults.
 - Sentence chunker: voice says copy AIRI's chunkTtsInput (minimumWords=4/maximumWords=12, CJK punctuation sets) + Open-LLM-VTuber's first-comma split; agent says use stream2sentence (Python: minimum_first_fragment_length=10, force_first_fragment_after_words=15) or Pipecat SentenceAggregator. These are different languages and parameters for the same component; the choice follows the unresolved Python-vs-TS decision.
 - AIRI control-token grammar: repos writes `<|ACT:{emotion,motion}|>` (colon) while agent writes `<|ACT {"emotion":...}|>` (no colon) and admits deepwiki summaries and base.yaml disagree; the parser (useLlmmarkerParser) must be read before adopting the grammar.
 - Live2D Motion Sync Web plugin target SDK: live2d says Web MotionSync R2 (Mar 2025) 'targets SDK R3'; the GitHub release page summary says R2 was updated 'to follow the changes in Cubism 5 SDK for Web R1'. Either way the plugin is 17+ months behind SDK for Web R5 (5-r.5, 2026-04-02) and no R5-compatibility statement exists (lookup 4).
 - deepseek-chat / deepseek-reasoner retirement: the deepseek researcher states retirement on 2026-07-24 15:59 UTC as fact; the shell researcher says only third-party pages claim this and asks for the official changelog. My fetch of api-docs.deepseek.com/news and /quick_start/pricing found only the three V4 model IDs and no mention of the legacy aliases either way, so the exact date remains unconfirmed from a primary source (lookup 1).
 - Open-LLM-VTuber as blueprint vs its frontend health: repos and agent recommend copying Open-LLM-VTuber's pipeline, protocol and Live2D vendoring, while repos also flags the frontend as possibly unmaintained. Confirmed: Open-LLM-VTuber-Web last push 2025-09-05 (almost 12 months), 176 stars, license 'Other/NOASSERTION' (the non-commercial Open-LLM-VTuber License) — so the backend pipeline is a fine reference but the frontend/renderer code is stale and non-commercial (lookup 5).
 - Electron version: shell says 'Electron 44 line'. Electron v44.0.0 shipped 2026-08-24 (4 days ago) with Chromium 152 / Node 24.18.1; for a production always-on-top WebGL window it is safer to pin v43 (or v42) until v44 has patch releases, given the open forward-mode hover bugs the shell researcher lists (lookup 3).
 - Star counts: Open-LLM-VTuber and Fay are both reported at exactly 13.5k stars by the repos researcher — plausible but suspicious; re-verify before quoting in a design doc.
 - Thinking-mode default: a summary of api-docs.deepseek.com/news claimed thinking is NOT on by default (must set thinking.type=enabled), contradicting the deepseek researcher; the dedicated thinking-mode guide says 'Thinking mode is enabled by default, with the default effort being high'. The guide is authoritative — the deepseek researcher is right, and every request must send {"thinking":{"type":"disabled"}} (lookup 1).
