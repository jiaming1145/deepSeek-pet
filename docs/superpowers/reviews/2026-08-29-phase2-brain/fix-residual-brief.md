## Findings to fix (all)

- **GC-1 [major] `packages/memory/src/history.ts` window/trim/visibleRows** — the 32k safety truncation still loses rows: `window()` drops the oldest prefix before `planTrim` sees it; `trim()` summarises only `plan.drop` from the truncated window, then advances `last_trim_id` to the exact cutoff, so the omitted prefix (e.g. ids 1–7 when `plan.drop` = 8–22) is never summarised. Fix: after resolving the cutoff, load and summarise EVERY row with `base < id <= cutoff` (including rows `visibleRows()` omitted); keep the id-bearing snapshot and re-validate it before commit; if the prefix is too large, summarise in bounded sequential chunks (≤ 24k tokens each) without advancing `last_trim_id` until the whole prefix is incorporated. Test: > 32k estimated tokens after `last_trim_id` → every row from the old pointer through the committed cutoff appears exactly once in the summariser input.
- **GC-2 [major] `packages/brain/src/turn.ts` settleEmpty** — the canned-empty path sets `settled = true` before playback and commits the full canned assistant row before `turnShown()`, so `send()`/`cancel()`/`bubbleCrashed()` cannot retire it as a shown-only interrupted reply, and a delayed `commitUser` can emit the canned sentence after a newer turn replaced `current`. Fix: the canned response follows the same `streamFinished/reported/settled` lifecycle as normal replies — emit + report while unsettled, defer the assistant append until `turnShown()`, let supersede/cancel persist only acknowledged sentences; keep `kind='system'` for the deferred row. Tests: supersede and cancel after the canned sentence is emitted but before `turnShown()` → no full row, only acknowledged sentences as interrupted; `cancel()` while `settleEmpty` awaits a delayed append → cancel resolves only after retirement writes settle.
- **GC-3 [major] `turn.ts` enqueue/commitUser/send** — the write chain swallows failures: `enqueue()` catches and resolves, `commitUser()` sets `committed = true` before the queued write runs; a failed user append + supersede loses the text with no row; a failed assistant append is reported as success. Fix: two promises per operation — an operation promise that keeps rejection for the state machine, and the caught barrier promise only for ordering; `userCommit: 'none' | 'pending' | 'durable' | 'failed'`; a superseding turn awaits a pending commit and carries the prior text forward only if it failed; a failed assistant append surfaces as an explicit persistence-error path (warn + `brain:error` hint `storage`, never "committed"). Tests: reject a pending user append then supersede → text not lost / not treated as durable; reject the assistant append → turn not reported as fully persisted.
- **GC-4 [major] `packages/brain/src/deepseek.ts` parseSseLine/streamOnce** — malformed JSON data frames are skipped; valid delta → malformed frame → `[DONE]` completes with content silently missing. Fix: a malformed NON-EMPTY data frame is a `DeepSeekError('server')` (retryable only via the existing `!sawDelta` gate) after logging only its length; also detect an explicit provider `error` object inside a 200 SSE body. Never include frame payload in the exception or warning. Test: delta + malformed + [DONE] rejects; logs contain only the length.
- **GC-5 [major] `apps/desktop/src/main/brain-service.ts` key:test handler + rebuildClient** — a key-test result is not tied to the key/generation it tested: testing literal key A while stored key B exists records A's result as B's status; rotating to B while A is in flight lets A overwrite `lastTest` later. Fix: generation-stamp key tests and capture a key fingerprint (sha-256 prefix, never the key); invalidate + abort prior tests on key change; return every result to its invoke caller, but update the broadcast `lastTest` only if the generation is current AND the tested key equals the stored key; an unsaved literal-key test never updates stored-key status. Test: delayed test of A, store B, resolve A → B's status untouched.
- **GC-6 [minor] `brain-service.ts` dispose + key:test** — in-flight key tests have no tracked controller/promise; they can continue after `dispose()` and call `refreshKeyStatus()` against closing windows. Fix: track controllers + promises; `dispose()` invalidates generations, aborts them, includes their settlement in the bounded drain; guard every post-await continuation with `disposed`/generation checks. Test: pending key:test, dispose → aborted/drained, no post-dispose refresh.
- **GC-7 [minor] `deepseek.ts` testKey** — ignores `readBodyBounded().truncated` and returns `ok:true` for a 200 body over `MAX_JSON_BODY_BYTES`. Fix: truncated → server failure; validate the bounded body is JSON with the expected completion shape before `ok:true`. Test: oversized 200 → `ok:false`.
